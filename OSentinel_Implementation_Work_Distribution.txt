EXECUTIVE SUMMARY & PROJECT OVERVIEW
--------------------------------------------------------------------------------
OSentinel is an intelligent, host-based security framework developed for Ubuntu
Linux. It combines heuristic rule-based detection with a 2-stage machine learning
pipeline to detect, classify, and mitigate both known security threats and unknown
zero-day anomalies in real time.

The system continuously monitors three critical operating system vectors:
1. Process Activity (CPU, memory, execution paths, process trees)
2. File System Operations (file modification rates, Shannon entropy calculation)
3. Network Connections (socket states, IP/port bindings, byte transfer rates)

To ensure clear ownership, scalable development, and modularity, the entire
implementation of OSentinel has been divided among three team members:

1. MEDARAMETLA LIKHITH (24BYB0054)
   Role: Telemetry Collection, Feature Extraction & Heuristic Rule Engine Lead
--------------------------------------------------------------------------------

A. ASSIGNED RESPONSIBILITIES:
   - Designing and implementing continuous probes across host processes, file
     systems, and network sockets.
   - Developing mathematical feature extraction functions (such as Shannon Entropy
     for ransomware detection).
   - Normalizing telemetry data into a standardized 8-dimensional feature vector.
   - Building the heuristic rule engine and JSON rule database for signature detection.

B. MODULES & FILES IMPLEMENTED:
   1. backend/modules/module1_process.py  (Process Collector)
   2. backend/modules/module2_file.py     (File System & Entropy Monitor)
   3. backend/modules/module3_network.py  (Network Connection & Traffic Monitor)
   4. backend/modules/module4_feature_extraction.py (8D Feature Vectorizer)
   5. backend/modules/module5_rule_engine.py (Heuristic & Signature Rule Engine)
   6. backend/rules/security_rules.json  (Rule Database Config)

C. KEY TECHNICAL IMPLEMENTATIONS:
   * Process Telemetry: Uses `psutil` to sample process tables every second,
     capturing PID, process name, CPU %, Memory %, user context, parent PID,
     and command line arguments.
   * File Entropy & Ransomware Probe: Uses `watchdog` to monitor write/create/delete
     events in target directories. Implements Shannon Entropy formula:
       H(X) = - SUM( P(x_i) * log2(P(x_i)) )
     Files with H(X) > 7.2 undergoing rapid modifications trigger instant ransomware flags.
   * Network Connection Probe: Captures active socket connections (`psutil.net_connections`),
     tracking foreign IP addresses, port numbers, connection states, and byte transfer rates.
   * 8D Feature Vectorizer: Aggregates raw metrics into a standardized array:
     [cpu_usage, memory_usage, file_write_rate, avg_file_entropy,
      network_conn_count, outbound_byte_rate, failed_auth_count, unusual_proc_count]
   * Heuristic Rule Engine: Matches telemetry against signature rules (mass file edits,
     suspicious listening ports like 4444, CPU spikes combined with high write rates).

2. KURRA LEELA KRISHNA (24BYB0004)
   Role: Machine Learning Pipeline, Risk Assessment Engine & Threat Simulator Lead
--------------------------------------------------------------------------------

A. ASSIGNED RESPONSIBILITIES:
   - Developing the 2-stage machine learning pipeline (Isolation Forest + Random Forest).
   - Creating synthetic training datasets with class balancing (SMOTE concepts).
   - Implementing model training, evaluation, and serialization (.joblib).
   - Designing the dynamic composite risk scoring formula and automated response triggers.
   - Building the controlled threat simulation suite for live security testing.

B. MODULES & FILES IMPLEMENTED:
   1. backend/modules/module6_ml_engine.py (2-Stage ML Detection Engine)
   2. backend/modules/train_models.py (Dataset Synthesizer & ML Trainer)
   3. backend/modules/module7_risk_assessment.py (Risk Scoring & Containment Engine)
   4. backend/modules/attack_simulator.py (Safe Threat Simulator Suite)
   5. backend/models/*.joblib (Pre-trained ML Model Artifacts)

C. KEY TECHNICAL IMPLEMENTATIONS:
   * Stage 1 Anomaly Detection: Uses Isolation Forest trained on normal host behavior
     to isolate zero-day anomalies without needing explicit attack labels.
   * Stage 2 Threat Classification: Uses Random Forest Classifier to categorize
     anomalies into: Ransomware, Data Exfiltration, Privilege Escalation, or Benign.
   * Dataset & Training Pipeline: Generates balanced synthetic telemetry datasets using
     SMOTE principles and serializes trained models to disk.
   * Dynamic Risk Scoring: Computes composite risk score:
       Composite Risk = (0.45 * Rule Score) + (0.55 * ML Score)
     If score >= 70, executes automated process containment (SIGSTOP/SIGKILL).
   * Controlled Attack Simulator: Executes safe, reversible attack routines:
     - Ransomware: Writes high-entropy encrypted blocks to /tmp/osentinel_sim/
     - Exfiltration: Triggers socket connection bursts
     - CPU Stress: Spawns high-utilization threads.
